# Failure mechanisms

Use for diagnosis or when copying an existing analogue. These mechanisms were source- or render-observed during the initial review; recheck current ownership before claiming a present defect. The task audit retains exact routes, quantities, screenshots and attribution history.

| Mechanism | Diagnostic and correction |
|---|---|
| Base-unit amount appears as a huge human value | Check the API amount contract and token decimals; use Balance without converting twice |
| Stacked labels concatenate | Text defaults to inline; explicitly choose a stack or field row |
| Same-level values have different sizes | Inspect the visible child and unit, not only parent classes |
| Long identities crowd principal columns | Use established list truncation and detail copy/full-value behavior; measure both local and document overflow |
| Registered/filter labels disagree across views | Reconcile domain status mapping, active filters, headings and counts |
| Tab/pager resets on refresh | Use stable shareable state where the task calls for it; verify direct URL and back navigation |
| Loading or failed request appears empty | Tie empty to a successful request with zero results; preserve independent error and loading ownership |
| Link-colored text has no destination | Use correct text semantics; retain its actual destination or text role |
| Zero-total chart implies proportions | Use a truthful zero state; render the actual zero-data state |
| Invalid input has no visible response | Verify rendered error ownership and accessible label/error association, not just an error state variable |

An old page is not automatically a safe template. Shared-component reuse also does not establish correct composition, state semantics or complete adoption. A source-confirmed risk is not a browser-verified failure; uncertain defects remain hypotheses until reproduced.
